# フロントエンド通知機能 要件定義書

## 1. 概要

本機能は、Firebase Cloud Messaging（FCM）とバックエンド通知 API を利用して、recwatch の管理画面で通知を受信、表示、管理する機能である。

FCM は即時通知の受信手段として扱い、通知履歴、未読件数、既読状態の正はバックエンド API から取得する。

## 2. 目的

- ログイン中のユーザーが重要なイベントをすばやく把握できる
- アプリを開いている場合は画面内で通知状態を即時反映できる
- アプリを閉じている、またはバックグラウンドの場合はブラウザ Push 通知を受け取れる
- 通知一覧、未読件数、既読状態をバックエンドの保存状態と同期できる
- FCM やブラウザ Push の制約が UI やドメイン表現へ漏れないようにする

## 3. 前提

- フロントエンドは React Router v7 の管理画面として動作する
- 通知対象は認証済みユーザーのみとする
- 通知配信には Firebase SDK を利用する
- バックグラウンド通知には Service Worker を利用する
- バックエンドは以下の API を提供する
  - `POST /notification-tokens`
  - `DELETE /notification-tokens`
  - `GET /notifications`
  - `GET /notifications/unread-count`
  - `PATCH /notifications/{id}/read`
  - `PATCH /notifications/read-all`

## 4. 対象ユーザー体験

### 4.1 通知許可

- ユーザーはログイン後、通知設定画面または通知パネルからブラウザ通知を有効化できる
- 初回ログイン直後にブラウザの通知許可ダイアログを自動表示しない
- 通知許可を求める前に、画面上で通知を有効化する操作を明示する
- ブラウザ通知が拒否済みの場合は、再許可のためにブラウザ設定が必要であることを画面上で示す
- ブラウザまたは環境が Push 通知に非対応の場合は、画面内通知と通知履歴のみ利用可能にする

### 4.2 フォアグラウンド通知

- アプリ表示中に FCM メッセージを受信した場合、通知ベル、未読件数、通知一覧へ反映する
- 重要度に応じて画面内トーストまたは通知パネル内の強調表示を行う
- 通知クリック時は `linkUrl` がある場合のみ対象画面へ遷移する
- 遷移前に対象通知を既読化する
- FCM 受信内容だけで完全な状態を確定せず、必要に応じて通知一覧または未読件数を再取得する

### 4.3 バックグラウンド通知

- Service Worker はバックグラウンドメッセージを受信し、ブラウザ通知を表示する
- ブラウザ通知にはタイトル、本文、重要度、遷移先 URL を反映する
- ブラウザ通知クリック時は既存タブがあれば該当 URL へフォーカスし、なければ新規タブで開く
- ブラウザ通知クリック後、アプリ起動時に通知一覧と未読件数を再取得する

### 4.4 通知一覧

- ヘッダーの通知ベルから通知パネルを開ける
- 通知パネルには新しい順で通知を表示する
- 各通知にはタイトル、メッセージ、作成日時、重要度、未読状態を表示する
- 通知が存在しない場合は空状態を表示する
- 一覧取得中、取得失敗、再試行可能状態を表示する
- 通知パネルから個別既読と一括既読を実行できる

### 4.5 通知設定

- 設定画面でブラウザ通知の有効、無効状態を確認できる
- 通知を有効化すると FCM トークンを取得し、バックエンドへ登録する
- 通知を無効化すると現在ブラウザの FCM トークンをバックエンドへ削除または無効化要求する
- 将来拡張としてカテゴリ別 ON/OFF を追加できる余地を残す

## 5. 機能要件

### 5.1 Firebase 初期化

- Firebase SDK の初期化はフロントエンドのインフラ責務として分離する
- Firebase 設定値は `VITE_` 環境変数から読み取る
- Firebase 設定値が不足している場合、通知機能は無効状態として扱い、アプリ全体は起動可能にする
- SSR 実行時に `window`、`navigator`、Service Worker API へ直接アクセスしない

### 5.2 Service Worker

- FCM 用 Service Worker を登録できる
- 既存の `public/sw.js` と責務が混ざらないよう、FCM 受信用の責務を明確に分ける
- Service Worker には Firebase Messaging のバックグラウンド受信処理を実装する
- Service Worker からクライアントへ通知クリック情報を伝達できる

### 5.3 FCM トークン管理

- ログイン後、ユーザー操作によって通知許可が得られた場合に FCM トークンを取得する
- FCM トークン取得時に VAPID key を利用する
- 取得した FCM トークンを `POST /notification-tokens` へ登録する
- ログアウト時、通知無効化時、またはトークン破棄時に `DELETE /notification-tokens` を呼び出す
- 同一ブラウザで登録済みのトークンを重複登録しない
- FCM トークンの再取得、更新、失効に備えて再登録できる
- トークンは UI やドメインモデルへ直接露出しない

### 5.4 通知状態管理

- 通知一覧、未読件数、受信中状態、エラー状態をフロントエンドで管理する
- アプリ起動時、ログイン復帰時、タブ再表示時に未読件数を取得する
- 通知パネル表示時に通知一覧を取得する
- FCM 受信時は未読件数を増やすか、バックエンドから未読件数を再取得する
- 複数タブを開いている場合、通知既読化後の状態ずれを許容しつつ、タブ再表示時に再同期する

### 5.5 API 連携

- バックエンド API のレスポンスはフロントエンド境界で正規化する
- API の `notification_id`、`link_url`、`created_at` などの外部形式を内部モデルの `id`、`linkUrl`、`createdAt` へ明示的にマッピングする
- API 失敗時は通知 UI のみ失敗状態にし、管理画面全体の利用を妨げない
- 既読化 API は成功後にローカル状態を更新する
- 一括既読 API は成功後に未読件数を 0 にし、一覧内の未読表示を解除する

## 6. 通知モデル

フロントエンド内部では以下の形に正規化する。

```ts
type NotificationSeverity = "info" | "success" | "warning" | "error";

type AppNotification = {
  id: string;
  type: string;
  title: string;
  message: string;
  linkUrl: string | null;
  resourceType: string | null;
  resourceId: string | null;
  severity: NotificationSeverity;
  isRead: boolean;
  createdAt: string;
  readAt: string | null;
};
```

## 7. 画面要件

### 7.1 ヘッダー通知ベル

- 未読通知がある場合は通知ベルにバッジまたはランプを表示する
- 未読件数が表示可能なスペースでは件数を表示する
- 未読件数が 99 件を超える場合は `99+` と表示する
- 通知ベル押下で通知パネルを開閉する

### 7.2 通知パネル

- ヘッダー右側から開くパネルとして表示する
- パネル上部に未読件数と一括既読アクションを表示する
- 通知項目クリックで詳細遷移、または既読化を行う
- 遷移先 URL がない通知は既読化のみ行う
- エラー通知、警告通知は視覚的に識別できるようにする
- キーボード操作とスクリーンリーダーで利用可能にする

### 7.3 設定画面

- ブラウザ通知の状態を表示する
- 有効化、無効化の操作を提供する
- ブラウザ通知が拒否済み、非対応、未設定、有効の状態を区別して表示する

## 8. 非機能要件

- FCM に依存したデータ形式を UI コンポーネントへ渡さない
- Firebase SDK の初期化、Messaging、Service Worker 登録、API クライアント、UI 表示を別責務として分ける
- 通知機能が失敗してもログイン後の通常操作は継続できる
- 通知許可状態やトークン登録状態を必要以上に localStorage に保存しない
- ブラウザ通知の権限、トークン、Service Worker 登録に関するエラーは開発者が追跡できる形でログ出力する
- ユーザーに表示するエラー文言は、復旧操作が分かる内容にする
- Service Worker と Firebase SDK のバージョン差異による破壊的変更に備え、実装箇所を局所化する

## 9. MVP 範囲

初期実装では以下を対象とする。

- Firebase SDK の導入
- Firebase 設定用環境変数の追加
- FCM Service Worker の追加
- 通知許可の取得
- FCM トークンの取得、登録、削除
- フォアグラウンド通知の受信
- バックグラウンド Push 通知の表示
- 通知ベルの未読表示
- 通知パネルでの通知一覧表示
- 未読件数取得
- 個別既読化
- 一括既読化
- 通知クリック時の画面遷移
- アプリ起動時、通知パネル表示時、タブ再表示時の再同期

## 10. MVP 対象外

- 通知カテゴリ別 ON/OFF
- メール通知連携
- 管理者による一斉通知作成画面
- 通知テンプレート管理
- 通知履歴のページング詳細画面
- モバイルアプリ向け Push 通知
- Slack、LINE、外部チャット連携

## 11. 実装方針

- Presentation は通知ベル、通知パネル、設定画面の表示と操作に限定する
- Application は通知許可、トークン登録、通知取得、既読化のユースケースを扱う
- Domain は正規化済み通知モデルと通知状態の判断のみを扱う
- Infrastructure は Firebase Messaging、Service Worker、HTTP API の詳細を扱う
- API レスポンスと FCM ペイロードは境界で内部モデルへ明示的に変換する
- 既存の `NoticeBtn` は通知パネルを開くトリガーとして拡張する
- 既存の `settings` ルートには通知設定セクションを追加できるようにする

## 12. 受け入れ基準

- 通知を有効化すると FCM トークンがバックエンドへ登録される
- 通知を無効化すると FCM トークンの削除または無効化 API が呼ばれる
- フォアグラウンドで通知を受信すると通知ベルの未読状態が更新される
- バックグラウンドで通知を受信するとブラウザ通知が表示される
- 通知ベルから通知一覧を開ける
- 通知一覧で未読通知と既読通知を識別できる
- 通知クリック時に指定 URL へ遷移できる
- 個別既読と一括既読ができる
- ページ再表示後もバックエンドの未読件数と整合する
- 通知機能が利用できない環境でも管理画面の基本操作は継続できる
